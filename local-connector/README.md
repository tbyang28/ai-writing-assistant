# 本机模型连接器

将自己电脑上的 **Ollama / LM Studio** 接入 AI 写作助手。Node.js ≥20，生产零依赖。云端网页无法扫描用户电脑，因此需要在运行模型的电脑上主动启动本组件。

## 使用

1. 安装并启动 Ollama（`127.0.0.1:11434`），或 LM Studio 的 OpenAI 兼容本地服务（`127.0.0.1:1234`），准备可调用模型。
2. 从 [可信项目仓库](https://github.com/tbyang28/ai-writing-assistant) 获取 `main` 分支源码，在仓库 `local-connector` 目录运行：

```bash
npm start -- --server https://ai-writing-assistant-api-o4nb.onrender.com/api
```

3. 登录写作平台，进入导航 **模型连接**，生成 5 分钟有效的一次性配对码。在终端提示中输入该码。生成新码会作废旧码，不要把码放进命令行参数或分享给他人。
4. 网页刷新后检查设备和模型，点击 **启用**，阅读并确认作品上下文的传输范围。
5. 在编辑器 AI 助手的模型下拉框中选择该设备的模型，使用写作或 Agent。

连接器保持前台运行；Ctrl+C、SIGTERM、stdin 关闭会停止连接器及模型请求。令牌只在内存中，每次重启需要重新配对。网页可禁用或撤销旧设备，每账号最多保留 5 个连接。

本地开发：`npm start -- --server http://localhost:8001/api`。HTTP 仅允许明确的 loopback 地址，其他服务器必须为 HTTPS；API root 路径以 `/api` 结尾，不接受 userinfo、查询串、fragment 或重定向。

可用 `--name 我的电脑` 手动命名设备，默认不上传操作系统主机名。`npm start -- --help` 查看参数。

## 数据和能力边界

- 仅访问以上固定 loopback 端口，不监听本机端口。任务不能指定任意 URL、文件路径或命令，不扫描内网。
- 上传设备名、模型清单、已确认能力和检测到的 CLI 名称。对 PATH 中的 claude/codex/copilot 只检查文件存在与可执行权限，不执行，不读取其 OAuth、配置、Keychain、浏览器资料或登录凭证。检测到 CLI 不代表可以调用它。
- 新连接默认禁用，启用后还需选择本机模型。该次生成的作品信息、人物、大纲、章节、检索片段和当前草稿等上下文会经平台发送到这台设备；生成结果返回平台。
- Ollama `/api/show` 声明 tools 才开放工具；LM Studio `/v1/models` 不证明工具能力，v1 默认关闭工具。模型上下文信息可能是理论上限，需确保本机服务的实际加载配置一致。预算不足会明确报错，不截断当前任务。
- 工具由平台服务器校验并执行；连接器不会执行工具。人物/灵感保存仍需网页逐项确认提案，章节正文仍需审阅后应用。
- 本机模型失败、断线、停用、撤销不触发云端模型回退。RAG 和 embedding 继续使用平台供应商，因此不是完全离线运行。
- 可选显式设置 `AI_WRITING_OLLAMA_API_KEY` / `AI_WRITING_LMSTUDIO_API_KEY`，仅发送到对应的固定 loopback 服务，不上传平台。不自动导入任何已有密钥。
- 自动化运行可用 `AI_WRITING_API_ROOT` 和 `AI_WRITING_PAIR_CODE`，需保持 stdin 打开；不要记录环境变量或将配对码写入脚本仓库。

## 故障处理和上限

没有模型：确认服务在固定端口启动并已加载模型。鉴权服务需要显式提供对应本机 key。配置不同端口的服务在 v1 不会被发现。

显示离线：连接器应保持运行，网页手动刷新；服务端按最近 30 秒心跳判断。被撤销的连接无法重连，重新生成配对码。

不支持工具：可进行文本生成，但无法通过 Agent 检索作品/创建工具提案。需要工具时手动选择支持的模型。较小上下文可能容纳不了整套工具定义，请缩小资料或使用更大上下文模型。

取消：网页停止生成或连接器退出会取消本机 HTTP；取消已发送到平台的操作不会撤销已提交数据。

每设备最多 2 个在途任务，单任务 120 秒；输入 200KB、文本输出 20 万 UTF-16 code units、事件总量 1MB，服务器最多缓存 64 条待消费事件。结果逐条确认，仅对网络不确定的同一事件重试一次，不重新发起生成。

平台 v1 使用单后端实例内存任务队列，重启会丢弃配对码并使在途任务失败；不会自动重放生成。扩展为多实例前需要共享队列和配对存储。

```bash
npm test
```

包含 33 个实际测试与 1 个被 Node test runner 加载的辅助模块：固定端点、权限与不可信任务、能力降级、重定向、超时、流量限制、SSE 终态、取消、事件确认与去重、stdin/信号清理，以及真实 HTTP 假服务联调。实现验证不代表真实模型质量评测。测试与浏览器联调均未消费真实模型额度。
