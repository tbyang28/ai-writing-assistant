# AI 助手操作体验：开源交互参考

调研日期：2026-10-01。用户重点：选中文字、续写润色、应用结果更顺手。本文是调研结果和建议，产品行为尚未修改。

## 推荐方向

以 Plate 的上下文菜单和结果审阅状态为主要参考，结合 Novel 明确的写回动作、AFFiNE 的选区入口。在现有 Vue 编辑器上缩短操作路径，继续复用现有修改预览、原文校验和撤销能力。

建议流程：选中文字 → 就近选择润色/校对/扩写 → 输入可选要求 → 查看局部差异 → 接受修改或继续调整。

## 当前代码中的具体卡点

本地检查基于社区交付版本 a506659。

1. **操作入口离正文较远**：EditorView 的 textarea 捕获选区后把内容传给 AiPanel；正文附近没有 AI 快捷入口。
2. **审阅有两层**：AiPanel 已展示生成结果或 Diff，再点“预览写回/预览这次变更”，EditorView 又切到 ChangePreview，最后接受。这个路径可以合并为一次局部审阅。
3. **续写位置固定**：AiPanel 的 writeRange('continue') 固定使用整章长度作为插入位置；光标在中间仍然写到章末。
4. **部分重试操作不直观**：润色的“重试”只重新显示要求输入，仍需再次发起生成；普通续写结果没有对应的直接再试按钮。
5. **生成缺少停止入口**：ai store 的流式 fetch 没有 AbortController signal，面板没有停止按钮。
6. **长章预览容易打断定位**：ChangePreview 接收修改前后的整章内容；小段修改也显示整章差异。接受后只更新选区数据和 textarea 高度，没有显式恢复输入焦点、光标与原滚动位置。

## 第一轮建议

- **选区工具条**：选中文本后显示“润色、校对、扩写、自定义要求”；当前目标范围持续可见。窄屏采用编辑区底部工具条，避免遮住选区。
- **统一审阅**：结果直接显示选区及少量上下文的差异，提供“接受修改、插入到下方、再改一下、放弃”；整章预览作为可展开选项。
- **位置明确的续写**：提供“从光标续写”和“接在章末”；有选区时可在选区末尾接写。发送生成上下文与最终插入位置必须一致，不能只改变插入坐标。
- **连续调整**：保留原文作为替换基准，把上一版结果作为调整输入，接受之前不写入正式正文。首次请求与重试要锁定同一章节、选区和模型。
- **停止与继续编辑**：停止后保留已生成部分供查看；能明确重新生成。接受后回到原位置继续写作，撤销可恢复原文。

保留现有章节/原文快照校验，防止过期结果覆盖新内容。第一轮不引入选区模糊匹配或自动合并。

## 验收重点

- 正文中间续写确实插到选定位置，上下文不错误使用后文。
- 选区润色只改变目标文本；接受、放弃、撤销均正确。
- 查看或输入调整要求时，用户仍能确认原选区。
- 切换章节、正文变化、重复点击和停止后迟到的响应都不能误写正文。
- 长章节局部修改只需审阅一次，接受后保持阅读位置并恢复输入。
- 桌面键盘、中文输入法和窄屏操作可用。

推荐先实现上述操作闭环，再根据真实使用反馈决定是否引入更完整的富文本编辑器。

## 本次落地与验证

- 选中文字后出现润色、校对、接着写、自定义工具栏；选区快捷续写始终从选区后插入。
- 续写可选择光标/选区后或章末，发送的当前章上下文截止到插入位置。
- 在助手内审阅局部差异并直接接受/插入原文后，正文编辑器始终保留。接受按钮固定在助手底部。
- 重新生成保留模型和指令；“再改一下”使用上一份结果作为输入，原替换范围和原文快照保持不变。正文变化后明确重新捕获当前范围，沿用修改要求。
- 支持停止生成；部分内容保留为不可直接接受的草稿。旧请求和迟到响应不会干扰新请求。
- 写回及撤销恢复选区和滚动位置；继续手动编辑后隐藏旧撤销操作，避免覆盖后续写作。
- 保留选区外围空白、校对接口未处理的超过 3000 code point 的尾文。
