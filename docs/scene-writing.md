# 场景目标续写

首版目标是让长篇续写遵守作者本次的情节推进、信息保留和叙事视角，提供可定位的审阅与有限局部修订。入口在章节编辑器的 **AI 助手 → 写作 → 场景目标续写**。

## 作者流程

1. 输入自然语言意图，例如“让沈砚发现林照在撒谎，暂时不揭穿，不能揭露凶手”。
2. 点击“整理场景目标”。检查、编辑情节目标、禁止揭露的信息、叙事视角、场景终点及期望字数。
3. 点击“生成并审阅”。可选开启最多一轮局部修订，默认关闭。
4. 对照初稿、审阅证据和修订结果，点击预览写回，再在编辑器变更预览中确认应用。

结果追加在发起请求时的章末。生成不会保存正文或新增人物/设定。正文、章节、模型、账号或场景目标变化时，旧结果不能直接应用。停止、断线、缺少完成帧或失败的生成/审阅不产生可应用结果。

## 链路

- **规划**：一次请求将意图转换成可编辑计划，建议不自动成为作者确认的事实。
- **资料**：按意图与草稿末尾选择提及的人物和词面相关的大纲，取当前章节之前最近两章各 500 码点、草稿末尾 1200 码点，以及本书 RAG top-5。人物候选最多 120 个、大纲候选最多 80 个；词面筛选并不保证召回所有相关资料。普通续写的默认记忆策略不受影响。
- **生成**：用编辑后的目标约束正文。期望字数 200–1600，最终新增正文不超过 5000 UTF-16 单位；期望字数不是精确长度保证。
- **审阅**：最多 8 条，每条必须引用新增正文唯一出现的连续片段，并关联服务端构造的约束 ID。服务端排除不存在、歧义、重叠或类型不匹配的引用。范围为初稿中的 UTF-16 偏移，与编辑器选择范围一致。
- **修订**：仅在作者勾选时执行一次，最多 3 个可修订片段，原片段总长不超过 1200 UTF-16 单位。只接收片段 ID 和替换文本，服务端拼接全文；未经选择的文字原样保留。每项替换最多 1200 单位，并受两倍原长度/短片段 300 单位的进一步限制。目标缺失和风格建议不自动修订，以免借此重写全文。格式或范围校验失败时保留完整且已审阅的初稿，不应用部分修订。

每次生成/审阅使用同一份资料快照。场景链路不使用工具，每阶段单次调用统一 `AgentRuntimeService`，沿用模型路由、账号归属、结束原因、完整上下文预算、取消和尝试/用量记录。不要求本机模型支持工具调用；不支持结构化 JSON 的模型会明确报格式错误，不回退云端。计划一次请求，生成与审阅两次，可选修订再增加一次。供应商内部网络重试单独计为 attempt。整次 SSE 请求最多 240 秒，本机单任务仍受 120 秒上限约束。

## 审阅的含义

“冲突”是模型认为存在的约束冲突，服务端只验证证据来自哪里、是否准确定位，不能证明模型判断正确。禁止揭露、视角以及作者保存的人物设定可标为冲突；情节达成、风格、节奏、正文/检索/大纲片段只标为建议。检索正文中的说法不自动等于客观事实，大纲也不代表剧情已经发生。模型没有权限把推断升级为已确认记忆。

局部修订后不再调用模型复审，因此原审阅意见仍指向初稿，不表示问题已经解决。界面会提示作者对照检查。当前版本没有持久化人物知识状态、事实时间线或全书一致性证明。

## API

两个端点均要求账号 JWT 和本书归属；传入 chapter_id 时还要验证该章属于本书。连接器 runtime token 无权调用。请求对象拒绝未知字段。

`POST /api/ai/scene/plan/stream`：

```json
{
  "book_id": "作品 UUID",
  "chapter_id": "可选章节 UUID",
  "content": "当前草稿（最多 60000 UTF-16 单位）",
  "intent": "作者意图（1–1200 单位）",
  "model": "可选云端或本机模型标识"
}
```

`POST /api/ai/scene/stream` 增加：

```json
{
  "plan": {
    "goal": "情节推进（必填，最多600单位）",
    "withheld": "禁止揭露的信息（可为空，最多600单位）",
    "pov": "视角（必填，最多300单位）",
    "ending": "终点（可为空，最多400单位）",
    "targetChars": 800
  },
  "auto_repair": false
}
```

SSE 为 `stage → token（仅新增正文）→ stage → result → done → [DONE]`；规划不发送 token。阶段为 context/plan/draft/review/repair。result 包含 plan、draft、revised、findings、repairApplied、warnings 和各阶段 metrics。初稿 token 仅供预览，必须收到 result、done 和终止哨兵才能启用写回。错误以 error 帧传递，HTTP 开流后仍为 200。取消传播至当前阶段；后续阶段不会启动。结构化阶段期间发送 SSE 注释心跳，result 写入遵守背压。

## 可复现比较

合成案例位于 `backend-ts/eval/scenes/cases.json`，覆盖发现谎言但不泄密、有限视角与人物知识、通过动作/对话改变关系。它们不是用户作品，也不是质量提升证明。

```bash
node backend-ts/tools/evaluate-scenes.mjs --dry-run
```

dry-run 无网络请求。实际评测需要服务、一个**没有章节/人物/大纲/灵感的独立测试作品**、账号 JWT 和显式模型标识：

```bash
cd backend-ts
# 在环境中设置 SCENE_EVAL_TOKEN，不要记录或提交它
node tools/evaluate-scenes.mjs --execute \
  --api http://localhost:8001/api --book TEST_BOOK_UUID \
  --model deepseek-ai/DeepSeek-V4-Flash --out /tmp/scene-eval-new
```

实际运行会消费该供应商额度；本次实现验证只使用假模型，未执行真实模型质量评测。`--case lie-without-reveal` 可只运行一个案例。输出目录必须不存在，以防覆盖旧结果。脚本不修改测试作品。

普通续写通过可选 instruction 接收与场景链路相同的意图和计划，模型一致；普通续写与新链路各自的记忆策略、prompt 和编排仍有区别。先使用固定作者计划，规划调用和人工编辑计划的耗时不计入本比较。每案例普通续写至少 1 次请求，场景链路 2–3 次（普通 Agent 可能增加工具轮），内部重试另计。执行顺序随机，供审阅的匿名样本标签随机。

`results.json` 保留顺序、标签映射、初稿、修订、阶段计数和耗时；`blind-review.json` 隐去链路标签，供人工按案例标准评分：目标 0–2 分、是否泄密、视角违规、设定冲突、作者需要修改的字符数以及偏好。不要在评分前查看映射。普通接口未返回实际用量/调用次数的字段记为 unknown/null，不能视为零成本；需要账单比较时使用供应商实际 usage 或相应请求日志。只有实际测量后才能声明质量、延迟和成本的改善或退化。
